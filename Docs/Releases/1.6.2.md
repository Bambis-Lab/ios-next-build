# iOS Next 1.6.2 (Build 25) – Factory OAuth / MCP Contract

## Korrekturen
- JSON-RPC-Antworten validieren Protokollversion und zugehörige Request-ID, auch bei SSE mit mehreren Ereignissen.
- MCP initialize prüft die Protokollversion; begrenzte Tools-Paginierung erkennt wiederholte Cursor.
- Strukturierte MCP-Rückgaben sowie Textblöcke werden unterstützt.
- Ohne freigegebene Read-only-Tools oder erfolgreiche Abfrage wird nicht Verbunden angezeigt.
- Kürzere Request-Timeouts; abgebrochene OAuth-Anmeldungen hinterlassen keinen Ladezustand.

## CI-Nachweis
- iOS-Unit-Integrationstests prüfen PKCE S256, OAuth-Registrierung, Callback-State, Keychain-Restore, Token-Refresh, MCP-Initialize, SSE/JSON-RPC-IDs, Tool-Liste und Read-only-Allowlist.
- Preconnect-UI-Test prüft fünf Servicezugänge ohne Home Assistant.
- Der Xcode-Runner versucht eine unauthentifizierte Metadatenprüfung des realen Factory-Gateways.
- GATEWAY_METADATA=PUBLIC_CONTRACT_VERIFIED beweist NICHT einen erfolgreichen Login, eine authentifizierte iPhone-MCP-Abfrage oder eine signierte IPA.

## Sicherheit
- Keine Live-Write- oder Host-Steuerfunktionen. Keine Tokens im Repository oder Build.
- Der Nutzer muss die Systembrowser-Anmeldung auf seinem iPhone selbst genehmigen.
- Unsignierte Device-IPA muss für SideStore signiert werden.

## CI Keychain isolation (post-run correction)

The unsigned simulator rejects Keychain security calls with OSStatus -34018.
The production FactoryMCPService continues to use the real iOS KeychainStore by
its default credential provider. CI injects an ephemeral in-memory provider
solely to validate OAuth grant, refresh, restoration, and MCP protocol behavior.
This does not claim to validate real-device signing, Keychain entitlements,
or completion of the user's OAuth consent on the iPhone.
